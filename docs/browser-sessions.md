# 浏览器临时会话与重连

状态：0.3.0 后的开发项，规则先于实现提交。浏览器作为独立临时客户端，不与原生客户端同步身份，不按名称、IP 或浏览器指纹合并。

## 重连规则

配对后仍使用现有随机 Bearer token；有效期保持 24 小时。网页将凭证保存在当前 origin 的 localStorage，兼容旧版 sessionStorage。刷新、网络重连、关闭后重新打开以及同一 origin 的新标签页复用有效凭证，沿用设备 ID、名称、会话和群身份，不再次创建 browser UUID。

主动断开会撤销服务端凭证，并删除浏览器中的凭证；其他标签页同步断开。凭证到期或已被撤销时清除本地记录，重新要求配对。浏览器存储不可用时退回当前页面内使用，不阻止配对。

更换浏览器、清理网站数据、隐私窗口、宿主地址或随机端口变化后可能产生新临时身份。这些身份不与原生客户端合并，也不会凭昵称恢复其他身份的历史权限。

## 设备列表与历史

附近设备仍只展示在线身份。浏览器的直接会话离线后自动移到默认收起的“临时会话记录”，按需展开查看传输历史；没有消息且没有文字草稿的空会话不展示。已有原生客户端会话和群聊继续保留在主列表。

网络中断仍沿用现有在线判断的短暂宽限期，避免网络抖动时列表频繁闪动。正在查看的会话即使离线仍可继续查看；重连后自动回到主列表。收起历史不删除消息、附件、保存副本、群成员或数据库设备记录。

离线临时会话不参与主列表的昵称冲突编号，展开历史时再区分重名；未读消息数量仍保留。此修改整理界面显示，不伪造稳定物理设备身份。

## 数据模型与接口

继续使用 SQLite schema 2，无新表或迁移。browser_sessions.token_hash、device_id、expires_at 和现有 devices.kind 继续作为身份依据。服务端只存 token 的哈希，不回传其他浏览器凭证。

会话列表响应补充 peer_kind 和 has_draft，以持久化的设备类型及文字草稿判断临时历史，不通过名称或 ID 前缀猜测。全部历史仍由原有 principal_id 权限保护；重连仅持有有效凭证时恢复同一身份。

## 验证

覆盖关页重开、新标签页、刷新及网络重连复用身份；主动断开在多标签页生效；过期凭证重新配对；重名浏览器不合并；旧离线浏览器历史收起后可展开读取；空会话隐藏、文字草稿保留；原生会话和群聊保持可见。编译检查和浏览器测试不替代跨真实设备网络验收。
