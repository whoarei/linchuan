# 0.3.0 验证记录

本版在 0.2.0 的会话、群聊和 SQLite 存储上增加动物昵称、客户端入口、自绘桌面标题栏和签名在线更新，不变更数据库 schema。

## 自动化

- 24 项 Rust 测试：已有传输、群、存储和身份隔离验证；新增稳定昵称及词库、浏览器类型、名称保存与身份延续、版本数值比较、预发布／降级过滤、更新地址回退，以及真实接收和上传时的更新阻止、取消后的恢复。
- 15 项 Playwright 流程：保留单聊、群聊、文件下载、历史和移动布局；新增自动名字、连续换名及保存、旧浏览器名字兼容、同名显示、自绘窗口按钮与拖动／缩放的接口模拟、异步状态同步、启动失败仍可操作窗口、更新下载进度和跨页保留、签名失败禁止安装、传输阻止安装、重启重试及 Android 下载入口。
- 6 项 Python 发布签名测试：三个目标清单、篡改安装包、旧签名版本重放、篡改可信注释、错误下载地址／缺少目标，以及发布目录混入私密文件时拒绝发布。
- TypeScript／Vite、Rust fmt／clippy、Tauri 配置 schema 与工作流 YAML 检查，Android arm64 编译检查。

此前 CI 的两处更新测试断言抢在动态导入后的异步调用完成前执行；本版改为等待可观察到的调用结果，不用固定延时掩盖问题。

## 发布门槛

同一提交的 Build and verify 必须全部通过，再将 v0.3.0 tag 指向该提交。Linux 构建 DEB／AppImage 并在 Xvfb 中验证原生 UI 启动嵌入服务；Windows 构建 NSIS；Android 构建 arm64 release 并检查 ELF 对齐。

本地下载对应 run 的原生产物并核对来源和归档摘要；Android 对比旧版证书与 versionCode，使用原 keystore 签名并检查 APK／ZIP 对齐。更新签名沿用仓库固定公钥对应的独立密钥，并绑定 0.3.0 版本。

发布前验证三个实际桌面包的签名、latest.json 的目标与 URL，以及九个公开文件的 SHA256SUMS；发布后回读 Release 的 tag、draft／prerelease 状态和每个资产摘要。具体构建 run 与源代码 SHA 附于 GitHub Release 发布说明。

## 实测限制

Windows／Android 真机、系统安装器覆盖升级、不同 Linux 发行版的 DEB 提权安装和 AppImage 替换仍需实机验收。窗口与更新接口模拟、离线签名验证不能替代这些真实系统流程。真实 Wi-Fi 发现、多厂商后台、低磁盘、2 GiB 与长期压力仍未完整覆盖。
