# 固定接收目录与数据模型

开发代码：新的网络接收直接写接收目录，完成后登记 saved_files，不再先写应用缓存再自动导出。临时文件与最终文件位于同一目标磁盘，发布避免覆盖同名文件；Android 通过目标 URI 的文件描述符写入并完成发布。接收发布检查点用于数据库提交失败后的恢复，完成文件不参与缓存清理。原有自动导出队列仅继续服务旧缓存和用户明确要求的另存副本。

状态：0.4.0 提供。保存规则和数据模型已在实现前通过 21b93f6 单独提交，0.3.0 正式版不包含此功能。

## 使用规则

客户端默认将接收成功的文件、图片保存到系统下载目录下的“邻传”文件夹，无需每次选择位置。设置页可以更改目录，后续文件采用新目录；已有文件保留原保存位置。重名文件使用递增编号，不覆盖已有文件。

Windows／Linux 使用系统下载目录；Android 10+ 使用 MediaStore 的 Download/邻传，Android 7–9 使用同名公共下载目录并按系统要求申请存储权限。Android 自定义目录通过系统目录选择器授权一次并持久保留 URI 权限。目录不可写或权限失效时保留应用内文件并提示重试，不把保存失败标成成功。

本机收到并接收完成的附件自动保存；已配对浏览器的附件仍由该浏览器下载，不能写入宿主选定目录。网页下载位置由浏览器自己的设置管理，应用不能保证取消浏览器的逐次询问。

消息中提供保存状态、打开文件、打开文件夹和失败重试。清理应用缓存不会删除接收目录中的文件；有待保存或保存失败的接收副本暂不清理。历史附件的应用内副本已清理时，已保存的文件仍可从消息打开。

0.5.3 起用“复制到其他位置”和“移动到其他位置”替代重复保存副本的按钮，均通过系统目录选择器选取目标。复制不更新 saved_files；移动成功后更新实际目录、文件名和位置。移动在目标写入完成后更新位置，再删除源文件；记录写入或源文件删除失败时回退并保留源文件。外部文件管理器移动文件不会自动更新记录。详见[大文件与文件操作](large-files.md)。

Android 默认目录的“打开文件夹”进入系统下载管理器；自定义目录尝试打开所选文件夹，具体显示由系统文件管理器决定。保存目录变更只影响后续保存，已有副本不搬迁。

## SQLite schema 2

使用现有 app_settings 保存 receive_directory 和 receive_since（首次启用的 UTC 毫秒），以本地收到消息的时间排除升级前历史。Windows／Linux 为绝对路径；Android 为默认下载目录标记或持久授权的 content URI。该配置只经本机 Tauri IPC 访问，不通过局域网 HTTP API 读取或设置。

新增 saved_files：

| 字段 | 类型／约束 | 含义 |
| --- | --- | --- |
| message_id, file_id | TEXT，联合主键、外键指向 attachments | 附件稳定身份 |
| transfer_id | TEXT NOT NULL，外键指向 deliveries | 关联的本机传输 |
| name | TEXT NOT NULL | 保存时实际使用的文件名 |
| directory | TEXT NOT NULL | 该副本实际采用的目录标记 |
| location | TEXT NOT NULL，初始为空 | 完成后保存的绝对路径或 content URI |
| status | pending / saved / failed | 等待保存、已保存、失败 |
| error | TEXT，可空 | 最近保存错误 |
| updated_at | INTEGER NOT NULL | UTC 毫秒 |

本机已配置接收目录后，完成的入站传输在原有数据库事务中插入待保存记录；以附件身份去重。仅 recipient_id 等于原生设备 ID 的接收自动加入，不替浏览器身份导出文件。升级前的历史不批量导出；旧附件可通过消息的保存入口按需保存。

原生后台任务处理待保存记录，将应用内完整副本流式复制到用户目录；成功后记录位置，失败保留副本供重试。目录选择和本机文件打开均通过原生接口，传入附件／消息 ID 后由核心验证归属，不接受网页传来的任意源路径。设置改动可重新排队保存失败的记录。

复制过程占用活动任务名额，安装更新时不会中断正在进行的保存。文件已复制但记录写入失败时，当前运行期保留结果并只重试数据库写入，避免再次复制；重试仍记录实际保存时的目录。

迁移保留 schema 1 全部设置、身份、会话和文件，不改变已发布 0.3.0 数据。保存目录和保存记录不加入协议、群资料或浏览器时间线。文件系统／Android 内容提供器与 SQLite 无法原子提交，不宣称崩溃时存在跨系统事务。

## 验证范围

覆盖 schema 1 升级、默认目录、目录设置保存、自动保存及去重、重名不覆盖、跨浏览器身份隔离、目录失效／磁盘错误和重试、缓存清理保留已保存文件及待保存副本、重启恢复、桌面文件操作和 Android 权限／URI 路径。自动化或编译检查不替代 Android 目录提供器和桌面真实文件管理器验收。

本轮检查：TypeScript/Vite 构建、Rust fmt/clippy、30 项 Rust 单元／集成测试、18 项 Playwright 流程通过。新增测试包含真实 SQLite 升级、文件内容与不覆盖校验、重启去重、浏览器隔离、失败与换目录重试、缓存保护、导出成功后数据库失败恢复，以及原生 IPC 模拟下的设置与文件操作。

Android arm64 Rust 检查和 Gradle `:app:compileArm64DebugKotlin` 编译通过。本机缺少 GTK/WebKitGTK，未运行 Linux 原生界面；Windows 文件管理器及 Android 真机的 MediaStore、SAF 提供器、旧系统权限仍需实机验收，IPC 模拟不能替代这些检查。
