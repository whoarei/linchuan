# 大文件、动态空间与复制／移动

本页记录 0.5.3 起的大文件和文件操作规则；0.5.2 及更早版本仍使用单文件 2 GiB 和应用文件总量 10 GiB 的限制。

## 空间预算

取消上述两个固定容量限制。发送草稿与接收任务按磁盘实际可用空间准入，每个磁盘默认保留 2 GiB；同一磁盘的并发任务共享预留账本。

可分配空间 = 系统报告的空闲空间 − 活动任务尚未写入的空间 − 2 GiB。

已写入的缓存、历史文件及部分文件已计入系统磁盘占用，写入进度会减少对应预留，不再把它们重复扣减。任务准入串行检查并登记；取消、拒绝、失败或任务结束后释放预留。传输和本地复制期间定期检查剩余空间，并保留现有磁盘写入错误处理。

原生接收同时考虑应用内完整副本和接收目录的自动导出副本。如果两个目录在同一磁盘，10 GiB 文件在开始接收时约需 22 GiB 空闲；不同磁盘则各需 10 GiB 数据空间及各自的 2 GiB 预留。接收确认时重新检查，空间不足保持待确认状态，显示缺少空间的原因。

Windows 按卷标识归组；Linux 按文件系统设备标识归组。Android 本机目录查询 StatFs，默认下载与模拟共享存储映射到实际的数据卷，避免把同一磁盘当作两份独立空间。Android 外置卡的本地目录可单独计算；不能提供本机容量信息的文档提供器会明确提示选择本机存储目录，不假定存在足够空间。

大小及单批总大小使用浏览器可精确表达的整数范围，累计时检查溢出；仍受目标文件系统的文件大小和实际容量约束。每批最多 64 个文件。新端发送超过 2 GiB 的文件前检查接收端 `dynamic-storage-v1` 能力；旧端会得到需要升级的明确提示。

## 超时和清理

浏览器上传、核心接收和设备间上传取消固定一小时的总时长限制。连续五分钟没有新的文件数据或上传字节进展时终止。控制请求和等待用户确认仍保留原有独立超时。

活动草稿上传不参与过期清理；上传结束会刷新草稿活动时间。过期闲置草稿清理时释放空间预留。中断传输仍不提供断点续传，重启后保留中断状态。

## 文件操作与位置记录

已保存的原生文件提供四个操作：复制到其他位置、移动到其他位置、打开所在目录、打开文件。复制与移动会选择目标目录，并自动避开重名文件。浏览器继续提供下载功能。

- 复制：保留原文件；数据库中的 directory、location 和 name 均不变，后续打开仍指向原文件。
- 移动：采用先完成目标复制、同步到磁盘，再更新记录并删除源文件的流程；当前实现会短暂占用两份文件空间。更新后的 directory、location 和实际 name 持久化到 saved_files，重启后继续有效。
- 失败：目标写入失败不改变原文件或原记录；记录更新失败会清理新副本；源文件删除失败会回退记录并清理新副本。若系统同时阻止数据库回退，会保留两份文件并明确报告新副本位置，不声称移动成功。
- 清理应用缓存后，复制与移动仍读取已保存的文件，不依赖缓存副本。复制、移动和自动导出均计入活动工作，避免应用更新中断文件操作。

应用不会扫描系统磁盘追踪外部改名或移动。如果通过外部文件管理器移动了文件，旧位置会失效并给出明确提示。

## 验证

核心回归包含同盘和不同盘预算、并发准入、已写入空间不重复扣减、活动草稿清理保护、持续超过一小时的上传、五分钟无数据超时及部分文件清理。使用实际 2 GiB + 17 字节文件进行有界内存的 HTTP 上传和下载，并对完整内容计算 SHA-256；全量核心测试会执行此检查，需要至少约 4.1 GiB 空闲磁盘及相应传输时间。

文件操作回归检查复制不改原记录、重名文件不覆盖、移动后路径持久化、重启和清理缓存后的可用性，以及数据库写入失败或源文件删除失败时保留原文件与记录。浏览器回归覆盖四个图标的 IPC、取消选择、失败提示和移动后的地址刷新。

本轮已通过 46 项 Windows Rust 核心测试（包含实际大文件收发）、27 项 Playwright 流程、Rust fmt／Clippy、TypeScript／Vite 和 Windows 原生编译检查。桌面与手机分别检查四个文件操作图标和无横向溢出；Android arm64 Debug APK 构建通过。尚未在 Android 真机上操作系统目录选择器或执行文件复制／移动。正式发布记录见 [0.5.3 验证范围](validation-0.5.3.md)。
