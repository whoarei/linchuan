# 恢复 HTTP 设备连接

适用版本：0.5.1。局域网连接恢复 HTTP／WS；0.5.0 标签、HTTPS 安装包与发布验证记录作为历史保留，不覆盖已公开资产。

## 使用与协议

- 局域网设备和浏览器恢复 HTTP 访问，WebSocket 使用 WS；继续监听随机端口，不增加专门的服务节点。
- 设备发现与信息接口恢复 protocol=1，使用既有 groups-v1、signed-offers-v1、history-v1 能力，兼容 0.4.0 的 HTTP 设备。不向 0.5.0 的 HTTPS 端口发送明文，也不自动转换 HTTPS 地址。
- 扫码／打开地址后直接输入配对码，不再生成 CA、展示证书指纹、下载证书或要求导入信任。设备名称、开机启动、托盘、接收目录和历史界面继续使用。
- 保留 HTTPS 改造中对设备信息响应大小的限制、发现通道关闭后的退出处理和局域网请求绕过代理的行为。设备 ID、公钥记录和消息／群聊签名继续校验；这些校验不提供传输加密。

## 数据与迁移

继续使用 SQLite schema 2。设备 ID、名称、群、历史、草稿和接收文件不重建、不清空。0.5.0 留下的 tls_identity 设置不再读取或使用，保留原值，避免为回退引入破坏性迁移；无效的旧证书数据也不阻止启动。

HTTPS 改回 HTTP 会再次改变浏览器 origin，可能需要重新配对；浏览器原有记录仍保存在宿主，不跨协议自动授予访问权限。原生设备身份保持不变，发现到新的 HTTP 地址后沿用既有会话。

程序不自动修改系统／浏览器信任。如果此前手动安装了邻传本地 CA，HTTP 版本不再需要，可在原系统／浏览器的证书管理中自行移除。

## 边界与验证

HTTP 内容未加密，面向可信局域网。保留配对、访问权限、接收确认及消息签名；不将其描述为内容保密或对所有中间人攻击的防护。普通局域网 HTTP 页面通常无法使用浏览器的麦克风、摄像头和屏幕采集，后续会议能力另行设计。

验证无需证书的真实局域网浏览器访问、配对、WS 通知、文字／文件完整传输、协议 1 设备接入、旧 CA 设置与既有历史的跨重启保留，以及现有会话、群聊、接收目录、桌面启动／托盘和更新流程。GitHub 下载与签名在线更新继续使用原有 HTTPS，不随局域网传输回退。
