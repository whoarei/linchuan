# 邻传 v0.5.3

本版支持 Android arm64、Linux x86_64 和 Windows x64，支持超过 2 GiB 的大文件，并新增复制到其他位置和移动到其他位置。

## 调整与修复

- **大文件按实际空间传输**：取消单文件 2 GiB 和应用文件总量 10 GiB 的固定限制，按磁盘实际空闲空间检查，每个磁盘默认预留 2 GiB。同盘的应用缓存、接收目录副本和并发任务统一计算；已写入的数据不重复扣减。
- **慢速传输可持续进行**：取消固定一小时的上传总时长限制，改为连续五分钟无文件数据或上传进展时超时。正在上传的草稿不会被定时清理；取消或失败时释放对应空间预留，重试重新检查空间。
- **复制到其他位置**：替换重复保存到接收目录的按钮，选择目标目录后生成新副本，保留原文件和原位置记录，自动避开重名文件。
- **移动到其他位置**：目标写入完成后更新保存位置并删除源文件，后续打开文件或目录跟随新位置，重启后仍有效。记录写入或源文件删除失败时回退；异常回退失败会明确报告并保留文件，不声称移动成功。
- **缓存清理后继续操作**：已保存文件的复制、移动和打开均可在清理应用缓存后使用；复制与移动计入活动任务，避免在线更新中断操作。
- **状态显示更准确**：设置页显示动态可分配空间和预留空间；文件信息可查看已保存的位置，复制与移动期间防止重复操作。

## 升级与使用

超过 2 GiB 的设备间文件传输需要收发双方均升级到 0.5.3 或更新版本；向旧接收端发送时会提示升级。仍受目标文件系统容量和文件大小约束，每批最多 64 个文件。当前接收保留应用内副本并导出到接收目录：同盘接收 10 GiB 文件在开始接收时约需 22 GiB 空闲。

复制不改变原位置记录；应用内移动成功后更新记录。外部文件管理器的改名或移动不会自动被追踪。移动通过先复制再删除源文件实现，期间需要额外的目标空间。

Android 支持能查询本地容量的下载目录和本机存储目录；无法查询本机容量的文档提供器会提示选择其他目录。浏览器继续使用下载功能，不提供原生文件夹或文件移动操作。

沿用 HTTP／WS、配对、数据库 schema 2、既有设备身份、会话、历史和接收目录。Windows／Linux 可在“关于”中检查更新或手动覆盖安装；Android 沿用 0.4.0 起的发布证书。

## 安装文件

- Windows x64：`Linchuan_0.5.3_x64-setup.exe`
- Linux x86_64：`Linchuan_0.5.3_amd64.deb`、`Linchuan_0.5.3_amd64.AppImage`
- Android arm64：`Linchuan_0.5.3_android_arm64.apk`
- 更新验证：三个桌面 `.sig`、`latest.json`
- 全部文件校验：`SHA256SUMS`

验证记录见 [0.5.3 验证范围](https://github.com/whoarei/linchuan/blob/main/docs/validation-0.5.3.md)。本版不提供断点续传；局域网 HTTP 面向可信网络。Android 真机文件操作、真实系统升级与跨设备 Wi-Fi 验收仍需持续验证。
