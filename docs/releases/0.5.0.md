# 邻传 v0.5.0

本版支持 Android arm64、Linux x86_64 和 Windows x64，将局域网通信升级为 HTTPS，为后续会议能力建设连接基础。

## 新增与改进

- **HTTPS 设备连接**：设备发现和手动连接统一使用 HTTPS，继续采用系统分配的随机端口，无需独立服务器。文字、图片、文件和群聊通知通过 TLS 加密，浏览器实时事件改为 WSS。
- **设备证书持久化**：每台设备使用独立的本地 CA，改名、重启和随机端口变化不会更换 CA。短期服务器证书随地址变化或持续运行自动续签，无需重复导入 CA。
- **客户端身份校验**：CA 公钥绑定既有设备身份，校验证书链、地址、有效期和握手签名；已知身份不匹配时拒绝连接，不自动降级到 HTTP。
- **浏览器信任入口**：连接面板和设置提供公共证书下载、SHA-256 指纹和首次信任指引；显示浏览器实际报告的安全上下文状态。程序不自动修改系统证书信任。
- **本机接口隔离**：原生 WebView 通过仅监听回环地址的内部接口工作，局域网对外只提供 HTTPS。客户端不需要导入浏览器 CA，也不放宽系统 TLS 检查。
- **发现与启动检查**：发现信息通过 HTTPS 验证后才保存；修复发现通道关闭时的退出逻辑。Linux 启动检查使用本设备 CA 验证 HTTPS，局域网探测直接连接设备，兼容宿主配置代理的环境。

## 安装与升级

- **通信双方需一起升级到 0.5.0**：发现和信息协议升级为 2，旧 HTTP 客户端不再与新版互传。原消息格式与历史继续保留，不凭名称或 IP 合并身份。
- Windows／Linux：0.3.0／0.4.0 可在“关于”检查更新，也可下载安装包覆盖安装。保留应用数据时，设备 ID、名称、会话、群和文件历史沿用。
- Android：沿用 0.4.0 的发布证书，0.4.0 可直接升级。0.3.0 及更早版本使用旧签名，需卸载后重新安装，请先保留需要的数据。
- **浏览器首次需要信任证书**：从可信设备取得本地 CA，核对连接面板的指纹，再按系统／浏览器规则导入信任并重新打开 HTTPS 地址。只越过证书警告不保证音视频权限可用。
- 从 HTTP 改为 HTTPS 会改变浏览器 origin，需要重新配对；宿主中的旧临时会话历史不删除，新身份不会自动取得旧历史访问权。
- 保持 SQLite schema 2，CA 证书及私钥存于应用私有数据库；公共导出仅包含证书。清除应用数据或卸载后，需重新核对新 CA，并移除旧证书信任。

## 安装文件

- Windows x64：`Linchuan_0.5.0_x64-setup.exe`
- Linux x86_64：`Linchuan_0.5.0_amd64.deb`、`Linchuan_0.5.0_amd64.AppImage`
- Android arm64：`Linchuan_0.5.0_android_arm64.apk`
- 更新验证：三个桌面 `.sig`、`latest.json`
- 全部文件校验：`SHA256SUMS`

## 验证与边界

自动化包含 41 项 Rust 核心测试、27 项 Playwright 流程和 23 项发布脚本测试。真实受信任 CA 的 Firefox 测试覆盖 HTTPS 配对、安全上下文、WSS、完整文件下载及重连；默认 Chromium 验证未信任证书被拒绝。发布要求三平台构建、Linux 普通／静默启动、Android 版本与签名及 16 KiB 对齐、桌面签名和公开资产校验通过。

不同系统／浏览器的证书安装、真实系统安装升级及跨设备 Wi-Fi 仍需实机验收。首次认识设备采用首次使用信任；浏览器经宿主代理时，宿主可处理内容，逐段 HTTPS 不等于浏览器间端到端加密。本版不包含音视频会议、远程控制、离线补发或 Android 后台常驻。

详见 [HTTPS 连接说明](https://github.com/whoarei/linchuan/blob/v0.5.0/docs/https-connections.md)和 [0.5 验证范围](https://github.com/whoarei/linchuan/blob/v0.5.0/docs/validation-0.5.md)。
