# 邻传 v0.2.0

本版将邻传升级为会话式局域网传输工具，新增群聊和 SQLite 本地存储，支持 Android、Linux、Windows 与浏览器入口。

## 下载与升级

| 平台 | 安装包 | 要求 |
| --- | --- | --- |
| Android | `Linchuan_0.2.0_android_arm64.apk` | Android 7.0+，64 位 ARM，沿用 0.1.0 发布签名 |
| Linux | `.deb` / `.AppImage` | x86_64，Ubuntu 22.04+ 或兼容发行版 |
| Windows | `.exe` | Windows 10/11 x64，NSIS 安装程序，需要 WebView2 |

退出旧版后覆盖安装即可。Android 使用与 0.1.0 相同的发布密钥，支持覆盖升级。Linux AppImage 下载后先赋予执行权限：

```bash
chmod +x Linchuan_0.2.0_amd64.AppImage
./Linchuan_0.2.0_amd64.AppImage
```

FUSE 环境缺失时可追加 `--appimage-extract-and-run`。`SHA256SUMS` 提供四个安装包的 SHA-256；GitHub 自动生成的 Source code 是源码压缩包。

## 新功能

- **会话式界面**：电脑采用功能栏、设备与群列表、消息与输入区三列布局；手机从设备列表进入会话，固定提供设备、设置、关于入口。
- **本地历史**：SQLite 保存设备、会话、消息、群成员、传输结果、附件元数据和文字草稿；离线设备仍可查看历史。
- **群聊**：创建群、邀请与确认加入、修改群名、重新发送邀请和退出；每群最多 16 位成员。已同步名单的成员可直接互传，群主不承担消息转发。
- **逐人传输结果**：群里一条消息对应每位接收者的独立进度、完成、拒绝或失败状态，部分送达不会标成全员完成。
- **文件管理**：完整附件跨重启保留；清理缓存后保留文字和文件卡片，显示附件不可用；活动文件跳过清理。
- **设备管理**：设置中直接修改并保存设备名；桌面第二次启动聚焦已有窗口。
- **协议校验**：新增稳定消息 ID、签名的群资料与成员事件、重复消息去重及跨平台签名序列化规则；直接传输保留 0.1 协议兼容。

## 数据升级

首次启动从 0.1 的 `device.json` 迁移设备 ID 和名称，后续以 SQLite 为准。**0.1 未落盘的内存历史无法恢复**。本版将重启前未完成的任务标为中断，完整文件与历史继续保留。

每台应用独立保存自己的数据。浏览器身份隔离，配对凭证到期或宿主随机端口变化时，不保证按设备名称恢复原浏览器身份。

## 当前限制

- 使用 HTTP，未实现传输加密，仅面向可信局域网。签名核对协议元数据，不代表内容加密或完整防御首次连接的中间人攻击。
- 群消息面向当前已加入成员，离线成员不自动排队补发；新成员不自动获得旧历史。邀请或群资料通知未送达时，群主可重新发送。
- 单文件最大 2 GiB，每次最多 64 个文件，本机文件预算 10 GiB；文字最多 64 KiB。
- 应用和网页需保持运行；不提供手机后台常驻保证、文件夹传输或断点续传。
- 应用内下载入口使用系统浏览器保存文件。Windows 安装包未进行商业代码签名，可能提示未知发布者。

## 验证范围

发布检查覆盖 16 个 Rust 集成用例、独立 Python/Rust 签名固定向量、6 个 Playwright 流程、类型与生产构建检查，以及三平台安装产物构建。Linux 使用 Xvfb 验证原生启动；Android 检查 16 KiB ELF 与 APK 对齐，并验证发布签名。

Android/Windows 真机、实际 Wi-Fi 跨设备发现、厂商后台行为、2 GiB 文件与长期压力仍需继续验证。详情见 [验证记录](https://github.com/whoarei/linchuan/blob/v0.2.0/docs/validation-0.2.md)；[数据模型](https://github.com/whoarei/linchuan/blob/v0.2.0/docs/data-model.md)包含表、约束、权限与恢复策略。
