# 设备自动命名

自 0.3.0 提供；旧版已保存的名字继续沿用，可在设置中更换。

## 使用规则

- 客户端与浏览器统一使用“状态／性格＋小动物”的中文昵称，例如“摸鱼海獭”“打盹企鹅”“好奇水豚”。昵称不包含系统、浏览器类型或固定数字后缀。
- 客户端首次启动生成并保存名称，重启保持不变。浏览器预填昵称，只填配对码就能连接；清空名称也采用自动昵称。
- 设置页允许两种客户端修改自己的名称。“换个名字”填入一个与当前输入、当前已保存名均不同的昵称，点击“保存名称”后生效。换名不会更换设备身份或改写历史消息。
- 系统和浏览器类型作为副标题显示，例如主标题“摸鱼海獭”、副标题“Windows · Edge”。设备列表、单聊和群成员选择中出现重名时才附加设备 ID 短编号；短编号相同则加长。编号只用于显示，不写回设备名。
- 已有安装、迁移数据及浏览器保存的名称继续沿用，不因升级被覆盖。设置中的“换个名字”可以改用动物昵称。
- 浏览器在同一 origin 的 localStorage 中分别记住自动建议与最近使用的名称，兼容上一轮的名称存储键。隐私模式、清理存储或随机服务端口变化后，名称可能重新生成。名称记忆不等于恢复配对身份或历史。

main 的[浏览器临时会话](browser-sessions.md)另外保存有效配对凭证，使同一 origin 下的关页重开和新标签页在 24 小时有效期内复用身份；依靠凭证恢复，不按名称合并。此项尚未发布。

昵称允许重名；设备身份始终由设备 ID、凭证和公钥决定。系统及浏览器类型从原生平台或 User-Agent 粗略识别，不保证识别具体硬件型号。

## 实现与数据

`shared/device-names.json` 是前端和 Rust 共用的词库，包含 48 个状态／性格词、48 个动物名，共 2,304 个不同昵称；词库校验要求名称唯一并符合 1–64 字符约束。

`crates/core/src/names.rs` 为新的随机设备 ID 计算 SHA-256 并映射到词库组合，用于客户端首次启动和未提供名称的浏览器配对请求；名称随后保存在数据库，不因未来词库调整而覆盖。`src/names.ts` 使用浏览器随机数选择昵称，供首次网页预填和两种客户端的“换个名字”按钮使用。同名展示根据当前可见设备、单聊、群成员和本机身份计算，并在身份之间去重；历史消息继续保留发送时的名称快照。

`POST /api/pair` 的 name 字段可省略或留空，返回实际采用的 name。浏览器平台信息保存于现有 devices.platform，重启后保留；state.me.platform 与设备列表返回这些信息。

`POST /api/settings` 根据调用凭证修改当前 principal 对应的 devices.name；浏览器同时更新自己的运行期 Session.name。客户端改名仍更新 app_settings.device_name 和 mDNS 公告。保留 owner 的 state.me.auto_name 作为按其设备 ID 生成的初始昵称建议，界面“换个名字”每次重新生成。

使用现有数据库结构，无需新增表或迁移版本。改名不改变 devices.id、browser_sessions.device_id、群成员 ID 或会话 ID，也不改写历史消息中的发送名称快照。事务失败沿用现有回滚机制。

## 验证范围

覆盖共用词库有效性和唯一性、稳定昵称映射、客户端默认名保存及手动覆盖、浏览器省略／空名称配对、重叠 User-Agent 的平台识别和保存、同名不同身份、浏览器仅修改自身名称、改名后会话和历史保留、重启恢复，以及浏览器预填、免填配对、连续换名、保存、刷新和旧名称兼容。同名显示覆盖附近设备、已建立单聊及改名后的编号消退；移动设置页检查横向溢出。

本地通过：`npm run build`、`cargo fmt --all -- --check`、`cargo clippy -p linchuan-core --all-targets --locked -- -D warnings`、`cargo test -p linchuan-core --locked`（3 项单元测试、18 项集成测试）及 `npm run test:e2e`（9 项流程）。CI 继续构建 Android、Linux、Windows；不以浏览器模拟替代原生真机测试。
