# 桌面开机启动与托盘

范围：0.4.0 的 Windows／Linux 客户端。Android 本轮不增加开机启动、托盘或后台常驻通知；普通网页不提供宿主系统设置入口。

## 使用规则

- 设置增加“开机启动”，默认不主动启用，由用户开关控制；实际行为是在用户登录桌面后启动应用。开机启动时不弹出主窗口，后台服务和设备发现正常运行。
- 默认“关闭窗口后继续运行”，标题栏关闭按钮、Alt+F4 等关闭请求收进系统托盘，不中断传输。可在设置关闭此选项，恢复关闭即退出。
- 托盘使用现有应用图标，菜单提供“打开邻传”和“退出邻传”；Windows 点击图标也可恢复窗口。再次运行应用会恢复已有窗口，不启动第二份传输服务。
- 核心服务由原生启动逻辑初始化，不依赖隐藏 WebView 的轮询或 JavaScript 定时器。手动退出会停止服务和设备发现；退出不取消系统开机启动配置。
- 托盘创建失败时显示主窗口，关闭窗口按退出处理，不留下无法通过托盘恢复的隐藏实例。Linux 托盘显示取决于桌面环境对 AppIndicator／StatusNotifier 的支持。

## 设置与数据

保持 SQLite schema 2，不新增表。app_settings 增加 close_to_tray，字符串 1／0，缺省为开启；设置写入成功后同步原生关闭策略，重启恢复。

开机启动由系统注册配置决定，使用 Tauri autostart 插件读取和切换，不额外在 SQLite 保存一份可能与系统设置冲突的状态。系统拒绝时提示错误并重新读取实际状态。

启动参数 --autostart 仅用于系统开机启动入口。托盘成功创建后才保持隐藏；正常手动启动、重复启动、托盘打开都会显示并聚焦窗口。开机启动和托盘命令只经本机原生 IPC 提供，不加入局域网 HTTP API，不把 owner 权限交给浏览器。

## 验证范围

验证设置保存及错误恢复、Android／浏览器入口隔离、窗口关闭请求进入后台、显式退出、重复启动恢复、启动失败和托盘创建失败的退路。发布构建保留 Linux 原生启动检查，并增加 --autostart 参数下的后台服务启动检查。接口模拟和编译检查不替代 Windows／Linux 登录桌面、真实托盘菜单与开机注册的实机验收。
